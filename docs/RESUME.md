# 简历与面试讲解

## 可验证项目描述

**Redteam Ledger — 可复现安全评测与回归证据台账**  
技术栈：Python / FastAPI / SQLite / React / TypeScript / pytest / Playwright / GitHub Actions。

实现安全检测器的可复现评测平台，冻结数据集哈希与评分器版本，记录分类混淆矩阵、Wilson 区间、目标错误和逐样本回归；通过命令行门禁及真实 HTTP 适配器接入防护服务。

English summary: A detector evaluation ledger with frozen synthetic fixtures, paired comparisons, Wilson intervals, target-error accounting and CI regression gates.

## 讲解顺序

1. 先展示一个失败或攻击场景，说明受保护的资产与信任边界。
2. 运行成功与拒绝路径，展示 API 响应和原始证据。
3. 打开核心模块，解释算法、状态或事务如何保证约束。
4. 展示测试及真实限制，并提出下一步实验。

## 常见追问

### 为什么目标错误不算拦截成功？

超时、服务崩溃或解析失败不说明防御有效。错误单独计数且使门禁失败，避免用不可用性伪造安全提升。

### 为什么两次比较必须同一数据集？

样本变了，结果差异可能来自难度变化而不是实现改进。哈希检查保证配对比较的基本可解释性。

### 如何避免评测集过拟合？

按攻击家族划分开发与测试集，冻结外部测试集，记录调参历史；不能不断添加已知失败样本后仍声称是未见测试。

## 诚实使用

- 项目属于 AI 应用安全与 Agent 安全工程，不等同于大模型预训练、对齐或安全研究成果。
- 可以写真实实现和通过的测试数量；不能虚构用户量、生产 QPS、降低风险百分比或企业落地经历。
- 此初版使用 AI 辅助开发。亲自复现、修改并解释关键模块后再作为自己的面试项目展开。
- 性能或防御效果必须带上数据集版本、样本数、运行环境与测量方法。
